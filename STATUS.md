### What was found

The findings share one root cause, and it is worth naming before the list, because it predicts where the next ones will be. **A hand-written count, list, or literal stops being true the moment the thing it describes grows, and nothing tells you.** The status taxonomy grew and four render literals did not. The migration set grew and one runbook sentence did not. The scoring engine grew a diagnosed-miss state and one skip list did not. In every case the code kept running and kept reporting success.

Its close relative is **the false clean**: a guard scoped too coarsely, or an assertion never proven to fire, reports green while the defect stands. Four of the sixteen new test files exist because a passing test proved less than it appeared to.

**CRITICAL — the interface lied to the commander about his own work.**

1. **The FULL DAY PLAN drew every logged block as untouched.** `public/static/app/core/shell.js` read `b.log_status` against the bare literals `done`, `partial`, `skipped`, and `missed` in four places. The status buttons write the Book 8.3 doctrinal spellings — `completed`, `partial`, `intentionally_canceled`. So a block the commander logged through the shipped interface came back from the server, failed all four comparisons, and rendered as if he had never touched it: no strikethrough, no colour, and the row still advertising points he had already earned. This is the defect the honesty engine exists to prevent, committed by the app itself.
2. **The operator runbook told a truth that had expired.** The gate sentence in `OPERATIONS.md` named `0005`, `0006`, and `0007` as the repository-authored migrations. It was written when that was true, and sections 5.4 through 5.24 were appended below it over the following weeks without it being touched. An operator following the runbook literally would have applied three migrations to production D1, run the verification, seen it pass, and stopped — with twenty-two migrations still pending and a gate that said he was done.

**HIGH — the honesty engine contradicted itself.**

3. **Recording a miss honestly cost more than hiding it.** `src/routes/miss-cause.ts` files `missed_block_diagnosed` at minus 5 points. The overnight engine then filed `missed_block` at minus 10 against the same block, because its skip list named only `missed` and a diagnosed block sits at `unreported`. One miss cost minus 15. Staying silent cost minus 10. That inverts Book 8.4 exactly. The Book 8.5 daily minus-30 cap hid it on heavy days, which is worse than not having the cap: a bound that hides a bug is not a fix.
4. **A successful appeal left the accusation standing forever.** The appeal route cleared `flag_type = 'missed_live'`. That flag name was replaced by `unreported_block` in `2c07344` and the UPDATE was left behind. `missed_live` has no other reference anywhere in the tree — nothing writes it, nothing else reads it. So the appeal refunded the points and left the flag in the commander's unacknowledged list permanently, with no path to clear it.
5. **The app announced a penalty it had never charged.** `shell.js`, `src/routes/day.ts` (twice), and `src/routes/agent-v1.ts` told the commander a closed window was "auto-cancelled" with "the penalty applied." Both halves were false: a passed window becomes `unreported`, and no points move. The copy described an engine that no longer exists and named a charge that was never taken.
6. **Client-supplied dates wrote false history into append-only logs.** `reviewed_on` reached the database raw, so `2099-01-01` parked a flashcard 73 years out **and** wrote a future-dated row into a journal that cannot be corrected. The sweep found six more raw event dates in the same file and one in another. Two concrete harms: every history read is `ORDER BY <event date> DESC LIMIT 100/200`, so one false row pins itself to the top and pushes real history off the end; and `cycle_days` carries `ON CONFLICT(user_id, chapter_id, cycle_day) DO UPDATE SET occurred_on = excluded.occurred_on`, so a future date does not merely add a lie, it **replaces a true record**.

7. **A week of completed work counted as a week of absence.** `src/state.ts` and `src/routes/recovery.ts` each hand-listed `status IN ('done','partial')` to decide whether a day had any activity in it. Under the doctrinal spellings a day of `completed` or `completed_late` work matched neither, so it read as a dark day. Two consequences, both of them the honesty engine misreporting his own history back to him: `GET /api/state` raised `needsCatchup` after three days of real work, and `POST /api/catchup` opened the six-part re-entry protocol — the one that names what was missed and re-seats the ratchet — for a man who had never left. Book 8.6 built that protocol correctly; its absence predicate had simply drifted from the taxonomy underneath it. Both queries now derive their list from `ACTIVITY_STATUSES` via `sqlStatusList`.

**MEDIUM — defences that were never proven to work.**

8. **`grace_minutes` fell through to NaN.** `src/enforcement.ts` read the setting and defaulted to 30, but no test ever set it, and a non-numeric value produced `NaN` from `Number(raw)`. Every comparison against `NaN` is false, so windows silently stopped closing — the failure mode of a safety setting being misconfigured was that enforcement quietly turned off.
9. **XSS was proven at the helper and nowhere else.** `test/xss-escaping.dom.test.ts` was green, and all four of its tests call `esc`, `nl2br`, and `mdLite` directly. That proves the tools work. It does not prove a single surface uses them.
10. **The progress lock was one line with no test.** `src/routes/learn.ts`, `if (up.status === 'locked')`, and nothing anywhere exercised it. The first draft of the replacement test was itself vacuous — `rows.slice(activeIndex + 1)` was empty, so it asserted over nothing and passed.
11. **Nothing had ever reviewed late.** Thirteen pre-existing scheduling tests all review on the due day. "Delayed review" has no feature code of its own; it is a property of three separate queues (SM-2 flashcards, FSRS review items, the fixed rhetoric ladder), and none of them had been asked what happens when the commander comes back after the day has passed.
12. **Migrations were only ever tested against the populated legacy copy.** `test/setup.ts` seeds 23 legacy tables and applies 0005 through 0029 on top of real rows. Nothing proved the same set applies cleanly to an empty database — the case a new install actually is.
13. **No record survived a job run.** Neither Cron nor a browser tick left a durable trace, so there was no way to tell whether the overnight engine had run, which crank turned it, or whether a run had been rewritten after the fact.

**MEDIUM — two tests that would have taught an operator to distrust the gate.**

14. **`test/enforcement-idempotency.test.ts` failed one day in seven.** It seeded one block, called yesterday 100% adherent, and did not know that `test/setup.ts` seeds a legacy block scheduled `mon`. Measured, not inferred: green with yesterday = 2026-08-23 (Sun), red the next day with yesterday = 2026-08-24 (Mon), where the unlogged legacy block took weighted adherence to 3/(3+1) = 75%, under the 80% victory threshold, so the branch under test never ran. The failure read "victory bonus was not awarded on the first pass" — a true statement about a premise the test had failed to establish, and a lie about the guard it exists to check.
15. **The rate-limit burst flaked under load and could not say why.** The assertion was a bare length check, and three different causes produce that message: a request lost to a database error under a loaded worker pool, a burst that outlived the 60-second window so the limiter was **entitled** to admit a second sixty, or a real regression. A message that cannot distinguish them teaches an operator to re-run the preflight until it goes green, and at the time of this finding the preflight was the only gate this repository had. (CI landed later the same day; see remaining risk 5.)

Findings 14 and 15 are not test hygiene. **A misleading diagnosis is the same failure class as a missing one**, and both of these pointed away from the truth.

### What changed

Each fix is stated with the mechanism, because in every case the mechanism is the point — replacing a hand-written literal with a derivation is what stops the finding from recurring.

- **One taxonomy, two consumers.** `src/block-status.ts` gained `isMissed` and `isUnreported` as exported predicates, and `public/static/app/core/block-status.js` was created as the client mirror: `hasLanded`, `isPartial`, `isHonestlyCanceled`, `isExcusedFromScoring`, `isUnreported`, `isMissed`, and `STATUS_BUTTONS`. The four bare literals in `shell.js` are gone. The buttons and the renderer now read the same predicates, so the value a button writes is the value the row tests — they cannot drift apart, because there is only one definition. `test/block-status-mirror.test.ts` asserts the mirror agrees with the server module set for set, so adding a status on one side and forgetting the other fails the suite.
- **Every SQL status predicate derives from the taxonomy.** `ACTIVITY_STATUSES` and `LANDED_STATUSES` are exported from `src/block-status.ts` and rendered into SQL by `sqlStatusList`, so no query hand-lists the statuses it cares about. This closed the absence miscount in `src/state.ts` and `src/routes/recovery.ts`, and it is the mechanism the module's own comment warns about: "a SQL query that hand-lists the statuses is exactly how `completed` came to earn nothing — the predicate above was updated, the four SQL literals were not." `test/block-status-honoured.test.ts` fails on any hand-listed status set in a query, so the next status the doctrine adds cannot be forgotten in SQL.
- **`rowStatusLine` replaced the untrue copy** in `shell.js`, and the three server messages in `day.ts` and `agent-v1.ts` were rewritten. A closed window now reads "NO STATUS YET — WHAT HAPPENED?" in amber, which is what actually happened and what Book 8.7 reserves colour for: red is for genuine risk, "never ordinary incompletion."
- **The diagnosed miss is charged once.** The overnight engine's skip list is derived from the taxonomy rather than hand-listing `missed`, so a block already diagnosed at minus 5 is not charged again at minus 10. The honest path is now the cheaper path, which is the whole of Book 8.4.
- **The appeal clears the flag that exists.** `unreported_block` replaces the dead `missed_live` in the UPDATE. `test/status-literal-drift.test.ts` fails on any flag literal in a route that nothing in the tree writes, so the next rename cannot leave an orphan behind.
- **Dates that record the past are bounded; dates that schedule the future are not.** That is the rule, and it is stated in the test file so it survives. Both mechanisms are accepted: `safeDate` clamps at `src/routes/day.ts:396`, and the route refuses outright at `src/routes/day.ts:233`. Seven raw event dates across two files were closed. `cycle_days` no longer accepts a future `occurred_on` that its upsert would use to overwrite a true record.
- **`getNumericSetting` in `src/repositories.ts` is the single reader for every numeric setting**, and returns the fallback unless `Number.isFinite(n)`. A misconfigured `grace_minutes` now falls back to 30 instead of turning enforcement off.
- **`OPERATIONS.md` gate sentence derives from the range it describes** — `0005` through `0029`, twenty-five migrations, sections 5.1 through 5.24 — and carries an inline note saying that adding a subsection is part of the same change. `test/migration-runbook-coverage.test.ts` enumerates `migrations/*.sql` and fails if any repository-authored migration lacks a rollback subsection, so the sentence cannot go stale silently again.
- **`migrations/0029_job_runs.sql`** creates the run record: which crank started it, when it finished, and append-only by trigger.

### How the new tests were proven to work

A test that has never failed is a claim, not evidence. Every fix above was verified by injecting the real defect back into the source, watching the intended tests fail with the intended message, and restoring. A surviving mutation means a real gap in the test; an *isolating* mutation — one that trips exactly one assertion — proves that assertion is individually load-bearing rather than carried by its neighbours.

- **The status taxonomy.** Reverting `shell.js` to the four bare literals turned `test/frontend-status-render.dom.test.ts` red on the logged-block cases. Adding a status to the server module without the mirror turned `test/block-status-mirror.test.ts` red. Both restored.
- **The diagnosed miss.** Restoring the hand-listed skip naming only `missed` produced the minus-15 charge and failed `test/diagnosed-miss-charged-once.test.ts` on the "honest path costs less" assertion specifically — which is the assertion that inverts if the defect returns.
- **The appeal flag.** Putting `missed_live` back failed both `test/appeal-flag-clearing.test.ts` and `test/status-literal-drift.test.ts`, from two directions: the behaviour and the orphaned literal.
- **The rate limiter (four mutations).** Widening the guard by 1000 tripped the security assertion ("more than the limit admitted"); narrowing it by 30 tripped the functional one ("fewer than the limit admitted", because a limiter that refuses early is also a defect); returning 500 instead of 429 tripped the diagnostic assertion that catches statuses the limiter never issues; declaring the window zero-length tripped the elapsed-versus-window guard. Four mutations, four distinct failures, each naming its own cause. That is what finding 15 was missing.
- **The calendar-dependent test (a three-run matrix).** Run A: remove the catch-all fix, leave the legacy block scheduled Monday-only — fails today, reproducing the original defect exactly. Run B: schedule the legacy block every day, keep the fix — passes, proving the fix does not depend on which weekday yesterday happens to be. Run C: both — fails, the worst case the fix exists to absorb. The fix logs every block the app itself considers scheduled yesterday, using the app's own day predicate from `src/repositories.ts` rather than a second copy of the weekday rule that could drift from it.
- **The clean install.** The first version of `test/migration-clean-install.test.ts` reported clean while the gap stood, because the emptiness guard sat inside the function it was guarding. **A check inside the function it checks is not a check.** Moving it to the call site made the measurement real, and made it fail before it passed.
